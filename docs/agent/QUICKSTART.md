# MegaRustDesk — управление через внешний Codex MCP

Встроенного чата и встроенного Codex в версии 0.3.3 нет.
Начиная с 0.3.2 обычный запуск оставляет один главный экземпляр для текущего
пользователя и сеанса Windows. Прежние подтверждённые копии из других папок закрываются;
активные подключения прежнего экземпляра могут завершиться. Внешний Codex/MCP остаётся
работать. Отдельное окно просмотра не считается вторым главным экземпляром.
Если файлы прежней копии не совпадают с её manifest, программа откажется закрывать её
автоматически и укажет PID для ручного завершения. Папки data не переносятся и не удаляются.
Задачи пишите в своём Codex CLI или в другом клиенте MCP на основном ПК.
Приложение передаёт ему только экран и ввод выбранной RustDesk-сессии второго ПК.

## Один раз на основном ПК
1. Распакуйте архив в постоянную папку с правом записи.
2. При уже установленном Codex CLI запустите «Подключить MCP к Codex.cmd».
   Он регистрирует только сервер `megarustdesk`; другие подключения сохраняются.
3. Перезапустите Codex, чтобы он загрузил новый MCP-сервер.

Альтернатива для CLI: `codex mcp add megarustdesk -- "полный путь к RustDesk-Agent.exe" --agent-mcp`.
Для другого MCP-клиента: stdio command — полный путь к EXE, arguments — `["--agent-mcp"]`.
После переноса папки повторите регистрацию, чтобы обновить путь.
Codex используется со своей обычной авторизацией и настройками; приложение его не запускает.

## Подключение второго ПК
Для первого перехода на обновляемую 0.3.0 распакуйте чистый bootstrap с GitHub Releases.
На уже рабочем ПК сохраните его собственную `data`; не копируйте `data` между компьютерами.
Если раньше распаковывали большой архив с чужой `data`, сохраните прежнюю папку отдельно
и запустите bootstrap в новой папке: новый ID нужно прочитать в окне второго ПК.
Далее обновления устанавливаются кнопкой в главном окне.

При обновлении с 0.2.0/0.2.1 закройте приложение на обоих ПК и распакуйте 0.2.2 поверх
существующей папки с заменой файлов. Сохраните папку `data`: она содержит прежний ID.
0.2.2 исправляет загрузку сохранённого ключа после перезапуска; обновите оба ПК.

0.2.3 исправляет локальную передачу больших MCP-ответов на основном ПК.
Для этого исправления принимающую сторону обновлять не требуется.
Сообщения передаются целиком; оборванные чтения screenshot/session_status имеют до трёх попыток
к той же сессии. Клики, текст, клавиши и действия управления не повторяются автоматически.
Потеря RDP-связи блокирует агентный ввод; привязка к компьютеру остаётся неизменной.

На втором ПК запустите `RustDesk-Agent.exe` из того же архива.
В разделе «Разрешить доступ к этому компьютеру» показаны ID и пароль.
Разрешите подключение или задайте свой пароль штатным способом RustDesk.
Codex на втором ПК не нужен. Автоматической установки службы и автозапуска нет.

На основном ПК запустите приложение, введите настоящий ID второго ПК и подключитесь.
Сначала управляете вы. Для передачи управления нажмите «Передать Codex».
Задайте задачу в своём внешнем Codex и укажите использовать MCP `megarustdesk`.
Он вызывает `list_sessions`, выбирает `bind_session` и получает удалённое изображение.
Пример: «Через megarustdesk открой Блокнот на подключённом втором ПК и введи проверочный текст».

Один процесс MCP привязывается к одной сессии; другой компьютер автоматически не выбирается.
Изображение передаётся как MCP image, ввод — прямо в RustDesk, без локальных кликов и буфера обмена.
Кнопка меняется на «Вернуть управление»: она сразу отзывает MCP-ввод и возвращает контроль вам.
При паузе или остановке со стороны MCP та же кнопка возвращает ручное управление;
повторно передать его Codex может только человек. После разрыва проверьте результат последнего действия.
Стрелка в заголовке сворачивает правую панель. Во время управления Codex в узкой полосе
остаётся кнопка «Я» для немедленного возврата контроля; её подсказка поясняет действие.
Для ручной вставки текста используйте Ctrl+V над удалённым экраном или «Вставить текст».
Текст отправляется только в этот сеанс и только при вашем контроле. Файлы/картинки таким
способом не передаются; автоматическая синхронизация буферов отключена. MCP не читает локальный буфер.
Сворачивание и закрытие просмотра сохраняют сеанс; «Выйти» закрывает его и блокирует инструменты.
Сам внешний Codex закрывайте в его собственном окне.

## Сеть и данные
Подключения по ID используют исходящие TCP/relay. Входящие порты, UDP/IPv6 punch и LAN discovery отключены.
Правила и уведомления брандмауэра не меняются. Нужен доступный сервер; задержка может быть выше прямой.
Принимающее приложение должно работать в доступной пользовательской сессии Windows.
Настройки находятся в `data` рядом с EXE; ключ MCP защищён Windows DPAPI для текущего пользователя.
Чаты/авторизация Codex остаются в вашем Codex; в этом приложении их нет.
Папка `data`, реальные пароли, ключи и история не включаются в архив.

Статус UNVERIFIED в manifest означает незавершённую полную проверку на втором ПК и чистой Windows.

## Обновления

В главном окне показана версия и кнопка «Проверить обновления».
Порядок: проверить → скачать → установить и перезапустить.
Клиент получает стабильные релизы из public URBoRTEX/MegaRustDesk без входа в GitHub.
Подпись Ed25519, hash и полный список файлов проверяются до замены.
Первый 0.3.0 опубликован как preview. Начиная с 0.3.3 обычные релизы доступны кнопке:
«Проверить обновления» → «Обновить до …» → «Перезапустить и обновить».
Повторно скачивать и распаковывать архив на клиентах 0.3.x не нужно.

Перед установкой завершите удалённые подключения и закройте MCP-клиент/Codex,
использующий EXE из обновляемой папки. Программа покажет блокировку, если они ещё работают.
Она не завершает их принудительно. `data` и настройки внешнего Codex сохраняются.
При неудачном запуске восстанавливается предыдущий payload; не удаляйте `.updates`
во время обновления. При ошибке отката сохраните папку и текст ошибки для диагностики.
