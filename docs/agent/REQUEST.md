## 3. Обязательная portable-поставка

Собери дистрибутив, например:

`RustDesk-Agent-Portable-win-x64.zip`

Внутри должен быть понятный главный файл:

`RustDesk-Agent.exe`

Допустима папка с EXE, библиотеками и внутренними компонентами. Если штатный механизм RustDesk позволяет надёжно собрать один самораспаковывающийся EXE, используй его, но не трать основное время на упаковку в один файл.

Для обычного запуска пользователь не должен:

- устанавливать RustDesk через установщик;
- устанавливать Rust, Flutter, Node.js, Python, npm или инструменты сборки;
- самостоятельно устанавливать Codex;
- запускать отдельные терминалы;
- вручную поднимать MCP-сервер;
- редактировать конфигурационные файлы;
- устанавливать Docker, WSL или виртуальную машину.

Все необходимые runtime-компоненты и библиотеки включи в поставку в поддерживаемом виде. Зависимости, которые нужны только разработчику, не должны требоваться конечному пользователю.

Главный EXE самостоятельно запускает внутренние процессы, проверяет их готовность и корректно завершает их при выходе.

Базовый режим должен работать от обычного пользователя без обязательного запуска всего приложения от администратора.

Не устанавливай автоматически службы, драйверы, задания планировщика и автозапуск. Не изменяй системный PATH и глобальные настройки других приложений.

### Данные и переносимость

Несекретные настройки, список подключений, историю задач и журналы приложения храни в собственной папке данных portable-приложения. Не используй абсолютные пути машины разработчика.

Проверь запуск:

- из другой папки;
- из пути с пробелами;
- из пути с кириллицей;
- после переноса распакованной папки.

Секреты храни подходящим защищённым способом. Если авторизация привязана к учётной записи или хранилищу конкретной ОС, при переносе на другой компьютер корректно предложи повторный вход.

В распространяемый архив не должны попадать мои токены Codex, пароли удалённого доступа, приватные ключи и история реальных задач.

Не обещай отсутствие любых системных следов Windows. Обеспечь отсутствие установки приложения и несанкционированных постоянных изменений системы.

## 4. Подключение моего второго компьютера

Предпочтительно сделай один portable-пакет с двумя понятными режимами:

- «Управлять другим компьютером».

Если принимающий компонент рациональнее вынести в отдельную облегчённую сборку, включи её в итоговую поставку и понятно обозначь назначение.

### На основном компьютере

Я запускаю приложение, выбираю удалённый ПК, подключаюсь и управляю им вручную либо через агента.

### На втором компьютере

Я запускаю portable-приложение, получаю ID и разрешаю подключение штатным способом RustDesk.

Предусмотри настройку доступа к моему компьютеру по индивидуальному паролю, чтобы не требовалось подтверждать каждое повторное подключение, пока принимающее приложение работает.

Не зашивай общий пароль в сборку.

Если на втором компьютере уже работает совместимый RustDesk, переиспользуй его, когда для реализации не требуется другой компонент.

Codex на втором компьютере не должен требоваться. Он работает на основном компьютере. При необходимости дополнительный удалённый исполнитель запускается принимающим приложением автоматически и тоже работает без установки.

Для первого использования допустимы понятные пользовательские действия: запустить принимающее приложение, разрешить доступ и авторизовать Codex. Всё техническое приложение настраивает самостоятельно.

Основной способ подключения — RustDesk. Не смешивай RustDesk ID с RDP-адресом. Если я предоставлю только RDP-доступ, определи, как использовать его для подготовки целевой машины либо как обеспечить нужное программное управление, сохранив изоляцию основного компьютера.

Проверь подключение через доступную сеть и штатный relay fallback. Не ограничивай готовность демонстрацией на localhost.

## 5. Локальный Codex внутри portable-приложения

Приложение должно управлять запуском Codex самостоятельно.

Для работы на компьютере без установленного Codex включи в поставку совместимый официальный runtime или бинарник со всеми необходимыми вспомогательными компонентами. Проверь доступность и условия распространения выбранной поставки.

Имеющийся локальный Codex можно использовать как дополнительный вариант после проверки совместимости, но его наличие не должно быть обязательным для portable-релиза.

Не требуй от меня ручного `npm install`, установки CLI или запуска `codex app-server` в терминале.

Сделай понятный вход в Codex через штатный механизм авторизации. Используй мою существующую авторизацию, если это поддерживается корректно; иначе предложи обычный вход.

Сохрани мои текущие настройки Codex и другие MCP-подключения. Конфигурацию этого приложения держи отдельно и не перезаписывай глобальные файлы.

Интеграцию строй по документации фактической версии:

- App Server — для взаимодействия приложения с Codex, его диалогами, событиями и подтверждениями.
- MCP-инструменты — для предоставления Codex доступа к выбранной удалённой сессии.

Не используй удалённую из актуальных версий команду `codex mcp-server`. Учитывай статус и ограничения App Server, зафиксируй совместимую версию и проверяй протокол по ней.

Проверь, что выбранная модель действительно доступна пользователю и получает изображения. Не выдумывай модели и параметры.

Не подключай платный API или другого платного провайдера автоматически. При исчерпании лимита покажи понятный статус и приостанови задачу.

Локальный Codex здесь означает локально запущенный клиент. Не называй облачную обработку модели офлайн-режимом.

Проверь совместимость механизмов ограничения доступа Codex с portable-режимом. Не отключай защитные механизмы ради запуска и не создавай системные учётные записи или службы без явной необходимости и отдельного согласования.

## 6. Как агент должен управлять удалённым компьютером

Основная архитектура:

Интерфейс RustDesk → локальный Codex → адаптер удалённых инструментов → конкретная сессия RustDesk → второй компьютер.

Доработай исходники RustDesk и используй существующие механизмы получения изображения и отправки событий ввода.

Агент должен получать изображение удалённого рабочего стола непосредственно из целевой сессии. Клики, текст и сочетания клавиш отправляй непосредственно туда же.

Не управляй удалённым ПК через клики по локальному окну RustDesk или mstsc.

Не используй локальные PyAutoGUI, SendInput, AppleScript и аналогичные средства для агентного управления моим основным рабочим столом.

Проверь, что агентный режим не включает глобальный захват локальной клавиатуры и не передаёт мой обычный ввод в удалённую сессию.

Локальный просмотрщик должен быть необязателен для выполнения задачи. Его фокус, размеры, положение и видимость не должны определять работу агента.

Если минимальный адаптер внутри RustDesk не подходит для конкретной платформы, допустим portable-исполнитель на целевом компьютере. Он должен запускаться автоматически, работать внутри нужной интерактивной сессии и входить в итоговый продукт. Объясни фактическую архитектуру.

### Требуемые операции

Реализуй небольшой набор инструментов:

- состояние подключения и целевой сессии;
- получение актуального изображения;
- выбор удалённого дисплея;
- клик и двойной клик;
- прокрутка;
- перетаскивание;
- ввод текста, включая кириллицу;
- сочетания клавиш;
- пауза, продолжение и остановка.

Названия инструментов выбери по архитектуре проекта. Не выдавай предполагаемые endpoints за существующее API RustDesk.

Изображение должно передаваться Codex как доступное ему изображение, а не только как путь к файлу на другом компьютере.

Снимок и действие должны быть связаны с конкретным компьютером, сессией и дисплеем. Учитывай размеры кадра, DPI, изменение разрешения и свежесть изображения.

Основной цикл:

Получить экран → выбрать действие → выполнить → получить новое состояние → проверить результат.

При потере изображения или соединения останови ввод. Не продолжай клики по старым координатам и не переключайся на основной компьютер.

Автоматическую синхронизацию локального clipboard в агентном режиме отключи. Передавай текст без изменения моего локального буфера.

## 7. Интерфейс готового приложения

Используй существующий интерфейс RustDesk и добавь компактную панель «Агент».

Мне нужны:

- просмотр удалённого экрана;
- поле задачи;
- кнопка запуска;
- сообщения и текущий статус агента;
- результат выполнения;
- кнопки «Пауза», «Продолжить», «Стоп», «Взять управление»;
- понятный статус подключения Codex.

Сделай интерфейс на русском языке.

В основной сценарий не выводи JSON, адреса MCP, внутренние идентификаторы, консольные команды и технические настройки. Диагностику можно открыть отдельно.

Обновления статуса не должны поднимать окно поверх моих приложений или забирать фокус.

### Поведение окон и процессов

Раздели три действия:

1. Сворачивание приложения — агент продолжает работать.
2. Закрытие только просмотра удалённого экрана — задача продолжается, приложение остаётся доступно в фоне или трее.
3. «Выйти» — задача останавливается, удалённое управление завершается, дочерние процессы закрываются.

После полного выхода не оставляй работающий скрытый исполнитель.

При нажатии «Взять управление» сначала останови агентный ввод. Одновременно управлять сессией должен один исполнитель.

## 8. Границы portable-режима и устойчивость

Базовый проверяемый сценарий: второй компьютер включён, пользовательская сессия доступна, принимающее portable-приложение запущено.

После его завершения, выхода пользователя или перезагрузки не обещай доступ без повторного запуска.

Если позднее понадобится доступ до входа в Windows или постоянный запуск после перезагрузки, это отдельный явно включаемый режим. Не устанавливай службу незаметно в рамках portable-сценария.

Обычные приложения должны управляться без повышения прав. Если задача требует взаимодействия с административным окном или UAC, покажи конкретную причину и используй штатную процедуру повышения. Не отключай UAC или защиту ОС.

Если человек одновременно работает на целевом ПК, не обещай независимость в одной пользовательской сессии. Для параллельной работы требуется отдельная подходящая сессия или VM; второй монитор сам по себе этого не обеспечивает.

Кнопка «Стоп» должна блокировать дальнейшие действия непосредственно в исполнителе, отменять очередь и отпускать удерживаемые клавиши и кнопки мыши.

После разрыва связи:

- останови отправку команд;
- восстанови разрешённое подключение;
- перепроверь целевой компьютер и сессию;
- получи свежий кадр;
- проверь результат последнего действия перед продолжением.

Не повторяй автоматически действие с неизвестным результатом: оно могло выполниться до разрыва.

Используй ограниченные повторы и таймауты. Показывай реальные ошибки и причины ожидания.

Сохраняй диалог задачи для продолжения, но не смешивай контекст разных компьютеров. Внешний текст на удалённых страницах не должен изменять разрешения агента и цель пользовательской задачи.

## 10. Проверка готовности

### A. Проверка portable-поставки

Запусти релиз на чистой поддерживаемой Windows-машине или VM без инструментов разработки и без установленного Codex.

Подтверди:

- EXE запускается двойным кликом;
- ручная установка зависимостей не требуется;
- внутренние процессы стартуют автоматически;
- доступен штатный вход в Codex;
- приложение не устанавливает службы и не меняет системный PATH;
- запуск работает из другой папки, включая путь с кириллицей и пробелами;
- полный выход завершает дочерние процессы.

Проверка только через dev-команду в репозитории не подтверждает готовность portable-релиза.

### B. Проверка подключения

На второй машине запусти принимающий portable-компонент.

### C. Проверка агента

Из панели приложения дай задачу:

«На удалённом компьютере открой текстовый редактор, введи “Проверка RustDesk Agent Portable — агент работает на другом компьютере”, сохрани новый файл в тестовой папке и покажи результат».

Проверь открытие приложения, ввод кириллицы, сохранение файла и итоговый снимок.

Этот сценарий должен выполняться через GUI, чтобы подтвердить работу управления экраном.

### D. Проверка отсутствия помех

Пока агент выполняет задачу, я должен спокойно печатать и работать в приложениях на основном компьютере.

Подтверди, что агент:

- не меняет мой локальный фокус;
- не двигает локальный указатель;
- не отправляет текст и сочетания клавиш в локальные окна;
- не изменяет локальный буфер обмена;
- не захватывает основной экран.

Проверь выполнение со свёрнутым просмотрщиком и после закрытия только окна просмотра.

Отдельно проверь паузу, остановку, ручную передачу управления и один разрыв соединения.

Если какая-то проверка требует моего участия и ещё не проведена, явно отметь её как непроверенную.

## 11. Что передать в конце

Передай:

2. Принимающую portable-сборку, если она отдельная.
3. Короткую инструкцию: что запустить на основном и на втором компьютере.
4. Как войти в Codex и дать первую задачу.
5. Как остановить агента и полностью выйти.
6. Версии компонентов и контрольную сумму релиза.
